# 踩坑 01：区块哈希计算错误

> 六段式：现象 → 排查 → 根因 → 5 方案 → Tradeoff 表 → 面试话术

---

## 现象

节点 A 挖出一个块，广播后所有其他节点都拒绝，日志报 `prev_hash mismatch`。
A 自己算出来的 `prev_hash` 和链上 tip 的哈希不一致；更诡异的是，A 把同一
个区块在不同进程里算出来的哈希都不一样。浏览器里的区块浏览器看到这个块
直接显示"无效块"。

## 排查

在本地写一段最小复现：构造 `Block(height=1, prev_hash=genesis.hash(), txs=[tx])`，
连续调用 `block.header_hash()` 两次，发现两次结果相同——说明哈希函数本身稳定。
然后把 A 节点序列化后的区块字节 dump 出来，和 B 节点反序列化后再算哈希对比：

- A 节点：`json.dumps(block.__dict__, sort_keys=True)` 后 sha256
- B 节点：直接按字段顺序 `height || prev_hash || merkle_root || timestamp || nonce` 拼接后 sha256

两者结果完全不同。进一步检查发现：
1. A 用 JSON 序列化，字段顺序虽然 sort_keys，但 `prev_hash` 在 JSON 里被
   编码成 hex 字符串，B 是 raw bytes，输入到 sha256 的字节流不一样。
2. A 的 `timestamp` 是 `time.time()` 浮点数，B 是 `int(timestamp)`，精度损失。
3. A 的 `nonce` 是 64-bit int，B 在拼接时按 32 字节大端序，A 按 8 字节——
   长度对不上。

## 根因

区块链哈希的本质是"对一个**确定字节流**求 SHA256"。任何序列化层面的不确定
（字段顺序、字节序、编码方式、精度）都会让最终字节流不同，哈希就不同。
这不是哈希函数的问题，是"输入不稳定"。

比特币和以太坊都用 **RLP 编码**（递归长度前缀）严格定义字段顺序和类型，
就是为了让不同语言、不同实现序列化出来的字节流逐字节一致。我们自己用
`json.dumps` 等于放弃了这个保证。

## 5 个方案

| # | 方案 | 原理 | 优点 | 缺点 |
|---|------|------|------|------|
| 1 | 手工拼 bytes | 每个字段固定长度、固定字节序拼接 | 完全可控、零依赖 | 易漏字段、改协议要改多处 |
| 2 | RLP 编码 | 递归长度前缀，类似 protobuf | 与以太坊对齐、跨语言一致 | 需要实现 RLP 编解码 |
| 3 | CBOR / MessagePack | 二进制 JSON | 跨语言 | 仍需固定 schema |
| 4 | Protobuf | IDL 定义结构 | 强类型、自动生成 | 引入编译链、字段号要冻结 |
| 5 | 签名结构（struct）序列化 | Python `struct.pack` | 简单 | 不支持嵌套、变长字段 |

### Tradeoff 表

| 方案 | 实现复杂度 | 跨语言一致性 | 协议演进成本 | 适合场景 |
|------|-----------|--------------|--------------|----------|
| 手工拼 bytes | 低 | 高（只要字段顺序固定） | 高（改字段要改代码） | 教学项目、单语言 |
| RLP | 中 | 极高 | 低（字段可追加） | 对齐以太坊 |
| Protobuf | 高 | 极高 | 极低 | 生产级多语言节点 |
| CBOR | 中 | 高 | 中 | 物联网/嵌入式 |

## 面试话术

"区块哈希对不上这种问题，本质是序列化不确定。我们一开始用 `json.dumps`，
发现 A 节点算出来的哈希 B 节点不认，因为 JSON 里 bytes 会被 hex 编码，
浮点数精度也会丢。后来改成手工按字段顺序拼 raw bytes：height 用 8 字节
大端、prev_hash 用 32 字节 raw、merkle_root 32 字节、timestamp 强制
`int()`、nonce 32 字节大端，所有节点立刻对齐。真实以太坊用 RLP 编码，
它递归地给每个字段加长度前缀，字段顺序在黄皮书写死，不同语言的实现
序列化出来的字节流逐字节一致，这就是为什么 geth 和 erigon 算出来的
状态根永远相同。我自己做项目时的经验是：**只要涉及哈希输入，绝对不要
用 JSON，必须用一个固定 schema 的二进制编码**。"
